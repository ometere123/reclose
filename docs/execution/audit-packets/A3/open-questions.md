# A3 open questions

These are the questions that remain for the external product/integration reviewer. They are not self-answered as PASS.

1. Does the application preserve the distinction between raw GenLayer lifecycle, Reclose DecisionOutcome, DecisionStage, child execution result and observed target post-state in every primary flow?
2. Is the five-band Incident Explorer causal presentation clear enough that a user cannot mistake evidence text for a protocol instruction or a semantic judgment for successful execution?
3. Is authority expansion prominent enough before signature, including resource/action bounds, Judge changes, human-override changes and activation delay?
4. Are the fixture adapter and optional index layer clearly labelled as convenience/read-model surfaces rather than protocol truth authorities?
5. Does the write-flow persistence boundary provide enough protection against accidental resubmission after navigation, refresh, polling errors or timeout-shaped states?
6. Do keyboard operation, focus order, contrast, responsive layout and reduced-motion behaviour pass a real browser/accessibility inspection?
7. Do malicious/oversized/unavailable evidence states remain understandable and inert when rendered in a real browser?
8. Are all primary R1 surfaces usable at mobile, tablet and desktop widths without hiding protocol-critical truth?
9. Is the current Studio-dev downstream child failure represented with enough precision that no user would read a successful Judge decision as a successful Kernel/Target action?
10. Are any P0/R1 product requirements still absent rather than merely awaiting browser/live-chain verification?
